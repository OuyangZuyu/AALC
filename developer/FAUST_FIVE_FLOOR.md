## 执行连接要求

1. 复用原版窗口初始化、输入后端、截图间隔和镜牢进入流程；从稳定主界面开始，不在半局中途接管。
2. 复用普通队伍的选人、寻路、商店、事件和结算；不复制一套镜牢状态机。
3. 每次进入战斗前按已读楼层组装本场 EGO 规则，复用现有 TURN 判定、名称识别和侵蚀／觉醒操作。新战斗、再次挑战均重置每回合尝试状态；名称读取失败按现有一般战斗回退。
4. 第5层切换困难仍使用原有难度切换与确认。最终结算沿用原版，并遵守当前“禁止领取所有奖励”开关。
5. 第4、5层观测应按目标名称翻阅目录，沿用进入观测、选择被替换候选、两次确认及最终拖入流程；尚无核实过的目录行列，不填造假的坐标。
6. 现有 `Shop.heal_sinner` 保持全体治疗。单人治疗入口为 `Shop.heal_single_sinner`，策略通过 `PROFILE.heal_in_shop` 调用；普通商店流程不会自动调用它。完整运行器接入时，应在其他商店消费前调用该策略。是否需要为治疗改变寻路优先级尚未指定。

当前策略默认按每层首次进入商店治疗一次建模，该频率仍待用户确认；不是已经实现、验证过的游戏操作。

## 单人治疗：2026-10-28 录屏及最新要求

复用原版治疗入口、金币读取和窗口内输入；增加单人选项及收尾。录屏中的头像位置按游戏客户区尺寸换算，不使用桌面绝对坐标，也不照搬事件页面的头像间距。

- 进入前读当前金币，小于 100 直接跳过。金币未知有界重读，仍未知则跳过，不把未知当作 0。
- 点击治疗入口 → “治疗一名罪人 / Greatly heal a single Sinner” → 底部浮士德头像。不检查黄色选中框。
- 每次选人后固定等待 3 秒，再在右下角查找“选择 / Select”。共最多 3 次选人尝试。
- Select 点击前重新读金币，点击后只以金币减少 100 为成功判据；不检查理智、血量、治疗结果文字或选中框。用户先提出检查理智 45，随后明确改为金币前后消耗，旧判据已取消。
- 一旦提交 Select，不再次付款。扣款读取失败或金额不符均返回未确认，不能记为成功或再次支付。
- 成功后点“离开 / Leave”回商店。失败走 Esc → 等待右下角“离开 / Leave” → 点击 → 确认商店；无法完成则抛出调用方提供的 RestartGame。
- 查找返回 None、False、空列表均按未命中处理；截图失败不用旧帧，每个本地重试预算包括截图失败。用户停止信号不吞掉。
- 当前语言分支复用 `auto.find_language_text`；已知中文只查中文，已知英文只查英文，未知语言由原版方法识别并同步。

分层契约：治疗内层处理有限重试与 Esc/Leave；无法安全返回才抛出 RestartGame。`PROFILE.heal_in_shop` 作为上一层捕获它，调用原版 kill_game/restart_game，返回 `completed=False, shop_ready=False, reason=game_restarted`；不消耗完成标记，不继续同一段商店操作。重启失败继续向上传递，不递归重启。现有普通 `Shop.in_shop` 捕获 RestartGame 后直接返回，不承担这个新分支的恢复；普通队伍行为保持不变。

独立五层运行器尚未接通，后续须由最外层消费 `shop_ready=False` 并重新检测游戏入口。不能对所有 None/异常统一盲目重启，也不能在未确认扣款后重新付款。当前单人治疗/策略层可离线验证，不代表已实现完整五层运行或全项目统一恢复。
